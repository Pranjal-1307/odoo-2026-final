# PeoplePay360 — Payroll Dashboard Specification

## 1. Purpose

The **Payroll Dashboard** is the central command center for the PeoplePay360 system.

It provides authorized users with a clear, real-time overview of:

```text
Employees

Active Contracts

Payroll Processing

Payruns

Payslips

Payroll Costs

Gross Salary

Deductions

Net Payroll

Pending Actions

Recent Payroll Activity
```

The dashboard should allow an Admin, HR Manager, or Payroll Manager to quickly understand:

```text
What is happening?

What requires attention?

Which payroll is currently being processed?

How much is being paid?

Are there any pending or failed items?
```

---

# 2. Position in the PeoplePay360 System

The Payroll Dashboard connects all major PeoplePay360 modules.

```text
01_LOGIN_RBAC_USER_MANAGEMENT
                │
                ▼
        AUTHORIZED USER
                │
                ▼
      12_PAYROLL DASHBOARD
                │
     ┌──────────┼──────────┐
     ▼          ▼          ▼
EMPLOYEES   PAYRUNS    PAYSLIPS
     │          │          │
     ▼          ▼          ▼
CONTRACTS  ATTENDANCE  PAYMENTS
     │          │          │
     └──────────┼──────────┘
                ▼
       PAYROLL ANALYTICS
```

The dashboard should not independently calculate payroll.

It should consume data generated by other modules.

---

# 3. Core Dashboard Principle

The dashboard is primarily a:

```text
VIEW

MONITOR

NAVIGATE

ACT
```

layer.

Architecture:

```text
SOURCE MODULES
       │
       ▼
DATABASE / API
       │
       ▼
DASHBOARD DATA AGGREGATION
       │
       ▼
KPI CARDS
CHARTS
ALERTS
TABLES
ACTIONS
```

The dashboard must always display data from the authorized user's company and scope.

# 8. Company Context

PeoplePay360 should maintain company isolation.

Therefore, the dashboard must clearly operate within the current company context.

Example:

```text
Company

ABC Technologies Pvt. Ltd.
```

All dashboard metrics must belong to the selected or authorized company.

Never combine:

```text
Company A Data
+
Company B Data
```

unless a future Super Admin role explicitly supports multi-company reporting.

CLEAR METRICS

        ↓
